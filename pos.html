Principles of OS

Module 1: OS Concepts & Process Scheduling

Q1. Define OS & its functions ⭐ IMP

Definition: An Operating System (OS) is a system software that acts as an intermediate between the user and computer hardware.

Four Functions of an OS:

  • Process Management: Creates, schedules, and terminates processes. Allocates CPU time for multitasking.
  • Memory Management: Manages RAM. Allocates memory to programs and deallocates when no longer needed.
  • File System Management: Organizes files and directories. Allows creating, deleting, and accessing files.
  • Device Management: Manages I/O devices (printers, disks). Uses device drivers to communicate with hardware.
Q2. Different OS Services ⭐ IMP
  • User Interface (UI): Provides GUI or CLI for users to interact with the computer.
  • Program Execution: Loads programs into memory, executes, and terminates them.
  • I/O Operations: Manages input and output devices.
  • File System Manipulation: Allows users to create, delete, read, and write files.
  • Communication: Enables communication between processes and computers over a network.
  • Error Detection: Detects hardware/software errors to maintain system stability.
Q3. System Calls & its types ⭐ IMP

Definition: A System Call is a mechanism through which a user program requests services from the OS kernel.

Four Types of System Calls:

  • Process Control: For process creation and execution. (Example: fork(), exit())
  • File Management: Operations like reading/writing files. (Example: open(), write())
  • Device Management: Control hardware devices. (Example: read(), ioctl())
  • Communication: Inter-process communication and networking. (Example: pipe(), send())
Q4. Operating System Structures
  • Monolithic Kernel: All system services are present in a single large kernel. Fast but difficult to maintain.
  • Layered Kernel: OS is divided into layers (hardware at bottom, UI at top). A request passes through layers sequentially.
  • Microkernel: Keeps only essential services in the kernel. Other services run in user space. Highly stable and secure.
Q5. Process & its states

Definition: A process is a program that is currently being executed. It contains program code, data, and current activity.

Process States:

  1. New: Process is being created.
  2. Ready: Waiting for the CPU to be assigned.
  3. Running: Instructions are being executed by the CPU.
  4. Waiting/Blocked: Waiting for an event (like I/O completion).
  5. Terminated: Finished execution.
New → Ready ↔ Running → Terminated
       ↑        ↓
       └─ Waiting ─┘
Q6. Process Scheduling & Queues

Process Scheduling: The activity of selecting a process from the ready queue and allocating the CPU to it. Main purpose is to keep CPU busy.

Scheduling Queues:

  • Job Queue: All processes present in the system waiting to be admitted.
  • Ready Queue: Processes ready to execute in memory.
  • Device Queue: Processes waiting for an I/O device.
Q7. Threads & Multithreading

Thread: A thread is the smallest unit of execution within a process. Threads of the same process share resources but have their own stack.

Advantages of Multithreading:

  • Improved Responsiveness.
  • Better CPU Utilization.
  • Resource Sharing (memory is shared easily).
  • Economy (Creating threads is cheaper than creating processes).
Q8. Race Condition & Critical Section ⭐ IMP

Race Condition: Occurs when two or more processes access and modify shared data at the same time. The final result becomes unpredictable and depends on execution order.

Critical-Section Problem: A critical section is a part of code where shared resources are accessed. The problem is to ensure no two processes enter their critical section simultaneously.

Solution rules: Mutual Exclusion, Progress, Bounded Waiting.

Q9. Mutex Lock ⭐ IMP

Mutex (Mutual Exclusion) Lock: A synchronization mechanism to ensure that only one process accesses a shared resource at a time.

  • Acquire/Lock: Process gets the lock before entering critical section.
  • Release/Unlock: Process releases the lock after finishing work.

If P1 has the lock, P2 must wait until P1 releases it. This prevents race conditions.

Q10. Semaphores (Wait & Signal) ⭐ IMP

Semaphore: An integer variable used by the OS to control access to shared resources and prevent race conditions.

  • wait() / P operation: Decreases semaphore value by 1. If value is 0, process must wait.
  • signal() / V operation: Increases semaphore value by 1. Tells waiting processes that resource is free.
Q11. Reader Writer Problem

It's a classical synchronization problem where multiple processes share a data resource (file/database).

  • Reader: Only reads. Multiple readers can read simultaneously.
  • Writer: Modifies data. Must have EXCLUSIVE access (no other reader or writer allowed).
Q12 (Multilevel queue) & Q13 (Multilevel Feedback queue) are Omitted.

Module 2: Memory & Disk Management

Q1. Deadlock & 4 Necessary Conditions ⭐ IMP

Deadlock: A situation where two or more processes are permanently blocked because each process is waiting for a resource held by another.

Four Necessary Conditions:

  • Mutual Exclusion: Resource can be used by only one process at a time (e.g., Printer).
  • Hold and Wait: A process holds one resource and waits for another.
  • No Preemption: Resources cannot be forcibly taken away from a process.
  • Circular Wait: A circular chain of processes exists where each waits for a resource held by the next.
Q2. Methods to handle Deadlocks ⭐ IMP
  • Prevention: Breaks at least one of the 4 necessary conditions. Prevents deadlock but low resource utilization.
  • Avoidance: Keeps the system in a safe state before granting resource (Uses Banker's algorithm).
  • Detection: Allows deadlock to happen, then detects it using a Wait-for Graph.
  • Recovery: Recovers from detected deadlock by terminating processes or preempting resources.
Q3. Deadlock Prevention ⭐ IMP

Ensures that at least one necessary condition never occurs:

  • Mutual Exclusion: Make resources sharable where possible.
  • Hold and Wait: Require processes to request all resources at once.
  • No Preemption: Forcibly take away resources if process is blocked.
  • Circular Wait: Impose strict ordering of resource types.
Q4. Deadlock Avoidance (Banker's) ⭐ IMP

Checks if allocating a resource will leave the system in a Safe State. If safe, request granted; else, denied.

Steps of Banker's Algorithm:

  1. Check if Request ≤ Need.
  2. Check if Request ≤ Available.
  3. Pretend to allocate (Update Available, Allocation, Need).
  4. Check for Safe State. If true, grant.

Formula: Need = Maximum - Allocation.

Q6. What is Swapping? ⭐ IMP

Swapping: Temporarily moving a process from main memory (RAM) to secondary storage, and bringing it back when needed.

Advantages:

  • Better memory utilization.
  • Allows more processes to run than physical memory size.

Limitations:

  • Slow operation (Secondary storage is slow).
  • Excessive swapping causes Thrashing.
Q7. Contiguous Memory Allocation ⭐ IMP

Contiguous Allocation: Each process is allocated a single continuous block of physical memory.

  • Fixed Partitioning: Memory divided into fixed size parts. Suffers from Internal Fragmentation (wasted space inside allocated block).
  • Variable Partitioning: Partitions created dynamically based on process size. Suffers from External Fragmentation (wasted space between allocated blocks).
Q8, Q9, Q10. Paging & Thrashing Theory

Q8. Demand Paging & Page Fault: Load page only when required. A page fault occurs when required page is not in RAM. OS finds free frame, loads page from disk, and restarts instruction.

Q9. Page Replacement: When RAM is full, OS replaces an existing page to load the new one. (Algorithms: FIFO, LRU, Optimal).

Q10. Thrashing: A condition where system spends more time handling page faults than executing processes due to insufficient frames.

Q13. Disk Structure & Scheduling

Disk Scheduling: Used by OS to decide the order of pending disk I/O requests. Aim is to reduce "Seek Time".

Seek Time: Time taken by disk head to move to required track.

  • FCFS: Served in arrival order.
  • SSTF: Shortest Seek Time First (closest request served first).
  • SCAN: Moves like an elevator till the end, then reverses.
